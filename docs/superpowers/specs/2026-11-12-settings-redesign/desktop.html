Output format and an example script
It prints JSON like this; id, title and url are required. repo is owner/name, github:owner/name, gitlab:group/name or a clone URL; without one, Maya picks the repository when you start. 
{"items": [{"id": "ENG-1204", "title": "Export reports as CSV",
  "url": "https://linear.app/acme/issue/ENG-1204", "status": "Todo",
  "labels": ["frontend"], "assignees": ["tiago"], "repo": "acme/web"}]}
#!/bin/sh
# My open tickets as Maya's work items (needs curl and jq).
curl -s -H "Authorization: Bearer $TRACKER_TOKEN" https://tracker.example.com/api/my-tickets |
  jq '{items: [.[] | {id: .key, title: .summary, url: .link, status: .state, repo: .repository}]}'

Release notes

What changed in each version of Maya.

0.53.0Running

New

  • The Issues tab takes items from any project management tool. In Settings → Work Items, add a custom tool with a name and a command that prints your items as JSON. Its items show on the Issues tab under the tool's name, and you can filter by it. If the command fails, Maya shows its error above the lists, and your other issues still show.
  • Start works on a custom tool's items too. A tool can have a second command that Start runs, so Maya can assign or move the item there; it gets the item as JSON on its input. When the item names no repository, Maya suggests one and you confirm it.
  • Set "your name there" for a tool, and Start asks before it takes over an item that is assigned to someone else.
  • Start no longer reuses a worktree that holds the work of another item. It tells you so instead.

0.52.2

Fixed

  • When GitHub's hourly request limit runs out, Maya now says so, with the time it resets ("GitHub's rate limit is used up until 08:58"), instead of saying your token was refused. She waits for the reset instead of asking again, and a pull request's badge stays on its card meanwhile.
  • Maya uses far less of GitHub's limit, which your account shares with gh and other apps: she asks GitHub only for what changed since she last looked, and those answers do not count against the limit.

0.52.1

Fixed

  • The Issues tab no longer shows issues from archived GitHub repositories or GitLab projects, including ones a rule names.
