# What's New After an Update Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first time Maya opens on a newer version, the computer and the phone show the release notes since the version that device last showed, with Maya's full-body art presenting them.

**Architecture:** A pure rule in `maya-core` decides, from the saved `last_shown_version`, the running version and whether the settings file existed at start, what to show and what to save. The desktop (`src-tauri`) and the phone (`mobile`) each expose the same two commands over it, `whats_new` and `whats_new_seen`. One shared front-end module filters the bundled `RELEASE_NOTES` and renders one modal; `styles.css` gives it the desktop look (Maya steps out of the left edge) and `mobile.css` the phone look (a pane with Maya as a banner).

**Tech Stack:** Rust (serde), Tauri 2 commands, TypeScript + Vite, vitest (jsdom).

**Spec:** `docs/superpowers/specs/2026-11-09-whats-new-design.md`

## Global Constraints

- A brand-new install shows nothing and saves the running version. "Brand-new" means the settings file did not exist when the app first loaded it at start, decided before anything at start can save it.
- An existing user with no saved version sees only the running version's notes, with no "Updated from" line and no count.
- A saved version equal to or newer than the running one shows nothing and saves nothing.
- Closing it in any way ("Got it", ×, Escape, a click on the backdrop; on the phone also a tab tap or Back) saves the running version. Quitting before it is closed saves nothing.
- Versions compare by number (`0.10.0` > `0.9.0`), never as strings.
- The `maya` command changes in no way.
- Copy, exactly (one footer on both, the plan's call over the phone mockup's shorter wording): kicker `Updated from <from>`; title `What's new in Maya <running>`; count `<n> versions since you last opened Maya.` (`1 version since you last opened Maya.` for one); the running version's heading carries a chip `This version`; footer `All release notes are in Settings › Release Notes.`; button `Got it`; the × has `aria-label="Close"`.
- The shared module imports nothing desktop-only (it runs on the phone too), as `src/devices.ts` does.
- Art: `src/assets/maya-full-body.png` (1024×1536). Colours only from the tokens in `src/styles.css` (`--panel`, `--gold`, `--gold-deep`, `--border`, `--muted`, `--on-gold`).
- Ships as a `feat`: bump from `main`'s version (`0.49.3` → `0.50.0` unless `main` moved) with `sh scripts/set-version.sh`, and a `RELEASE_NOTES.md` section, in one `chore(release): <version>` commit (CLAUDE.md).

## Review Focus

1. A Settings save after "Got it" must not put the old `last_shown_version` back: the desktop page sends its whole cached config to `set_config` (Task 2 test).
2. A notification tap or anything else that opened a card at start must not be replaced by the window; the window waits for the next start instead (Task 4 and 5 tests).
3. A saved version that is not a version (hand-edited, `""`) must not hide the window forever or crash: treat it as no saved version on an existing install (Task 1 test).
4. Notes that hold nothing to show for the offer (the running version missing from the file) must not open an empty window; it is marked seen instead (Task 3 test).
5. On the phone, Back with the window open closes it (and saves) instead of leaving the app (Task 5 test).

### Task 3: The shared window

  - `export function notesSince(offer: WhatsNewOffer, notes?: ReleaseNotes[]): ReleaseNotes[]`: with `from` null, only the section whose version is `running`; otherwise every section newer than `from` and not newer than `running`; file order (newest first); sections with no or unparsable version left out. Escape is the caller's (it owns `document` listeners).
